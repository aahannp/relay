The team.

Relay ships a team of built-in specialists. You hand one a job with a clear prompt. Each has its own instructions, model and effort. A lead agent can start several in parallel, each in its own git worktree.

How it works in practice

Three real stories from the last few days of building Relay with Relay.

Relay 1.10.10 → 1.10.11

A reply bug, fixed the same day

  1. A user reported: "Reply to selection does nothing."
  2. Sherlock reproduced it in a hidden window against the real Claude Code.
  3. The cause: Claude Code runs full screen and takes the mouse, so the terminal had no selection.
  4. The fix uses the text Claude sends when you release the mouse, with a test that drags, right-clicks and opens the box.
  5. A follow-up: the Reply button stayed on screen after sending. It got a test that failed first, then the fix.
Relay 1.10.8

A message can't answer a permission prompt

  1. Cassie's critique ranked it a top risk.
  2. Sherlock built the fix.
  3. Vera's review found one serious issue and three smaller ones. One example: a pane could stay marked "needs you" for good.
  4. Sherlock fixed all four, each with a test.
  5. Tess proved it against the real Claude Code permission dialog: 36 timed runs, and none answered the dialog.
Cassie

Doing less

  1. A design for a benchmark suite had four parts.
  2. Cassie's review asked of each number: "If it came out high or low, what would you do differently?"
  3. That cut it to two small pieces: CI time and task status history. A speed script that measured the wrong layer was dropped.

Workflow numbers, like reopened tasks and time to done, are being collected from Relay 1.10.9 and will be added here later.
